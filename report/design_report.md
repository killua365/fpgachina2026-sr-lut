# 基于 SR-LUT 的双 FPGA 图像超分辨率系统

## 1. 设计目标与实现范围

本项目面向本地图像、视频文件与 USB 摄像头的超分辨率处理和交互展示。目标是在 PYNQ-Z2 上完成固定 LUT 的硬件推理，在不降低算法输入输出分辨率的条件下优化实时显示，并提供可追溯的正确性与性能证据。

系统采用 PYNQ-Z2（Zynq-7020）与 Nexys Video（Artix-7 xc7a200tsbg484-1）。PYNQ 承担算法和界面，Nexys 承担 HDMI 输入、DDR 缓存和 DP 输出。工程基于 SR-LUT Model S 的查表方法，原算法参考与评分来源保存在 `src/third_party/algorithm_sources.zip`；本项目的工作重点是 RTL 实现、软硬件集成、数据完整性、显示缓冲和交互性能。

交付功能为 r15，板端包为 `r15_repack_20261020`。默认 DP 配置身份为 `26101201`；独立 VGA 兼容配置为 `26102101`。所用实现为 RTL、Python 和 ARM C，不包含 HLS 或 AI Engine 实现。

## 2. 系统架构

```text
图片 / 视频 / UVC 摄像头
         │
PYNQ PS：读取、等比适配、控制与缓冲管理
         │ AXI DMA
PYNQ PL：邻域 → 量化 → LUT 寻址 → 单纯形插值 → 旋转融合
         │ DDR 结果
PYNQ PS：Nearest 对照、界面、指标、快照与导出
         │ RGBX / VDMA 三缓冲 / VTC
HDMI 1920×1080 @ 30 Hz
         │
Nexys：HDMI 接收 → 帧检查 → DDR 完整帧缓存 → DP 扫描
         │
DP 1920×1080 @ 60 Hz → 显示器
```

图片使用五组 Set5 原生 HR/x2 LR/x4 LR 配对；视频和摄像头的算法输入为 480×270，摄像头固定 x4 输出 1920×1080。Fit/1:1 只调整查看方式，不改变算法分辨率。

选择 PS 负责输入、交互与文件系统，能够复用 PYNQ 和 Linux 的外设能力；将规则固定、重复执行的查表计算放入 PL。显示桥使用独立 DDR 完整帧缓存，解耦 30 Hz 输入与 60 Hz 输出，保留完整新帧和重复扫描的区分。

## 3. 算法与硬件设计

### 3.1 LUT 与数值合同

像素和 LUT 值均使用明确的整数表示。四维邻域量化后生成查表地址，按余数确定单纯形顶点和权重，再完成插值与多方向融合。参考模型按量化、邻域、寻址、单纯形、插值和输出分别实现，便于逐级比较。

| 配置 | 量化步长 | 每维采样点 | LUT 深度 | 每地址输出 | LUT 原始值容量 |
|---|---:|---:|---:|---:|---:|
| x2，4-bit 采样间隔 | 16 | 17 | 83,521 | 4 个 int8 | 334,084 字节 |
| x4，5-bit 采样间隔 | 32 | 9 | 6,561 | 16 个 int8 | 104,976 字节 |

上述容量指查表数组，不等于综合后的总 BRAM 占用。x4 的 4-bit 基线需要 1,336,336 字节查表值，项目保留其原始 NPY 用于算法来源与容量对照，正式硬件使用 x4 5-bit LUT。

`sr_lut_pkg.sv` 固定像素、权重和累加位宽；NPY 转 MEM 工具检查形状、数据类型、字节序及回读一致性。固定 LUT 和黄金数据已随工程提供，重建 FPGA 不需要重新训练模型。

### 3.2 PYNQ 数据通路

RTL 包括动态行缓存、RGB 调度、量化与地址生成、ROM、单纯形选择、插值/融合流水线、结果 FIFO 和 AXI 包装。PS 使用 AXI DMA 发送输入和接收输出；Overlay、DMA 句柄与缓冲区按代次管理，避免重载后继续使用失效对象。

CPU 侧采用预分配 RGBX 缓冲与 ARM 原生像素处理。像素校验与复制融合，减少重复内存遍历；仍检查完整输出的 X 字节。显示使用 VDMA 三缓冲，缓冲区仅在设备完成后转移所有权。冻结功能独立复制同帧输入及结果，避免后续采集或 DMA 覆盖快照。

### 3.3 Nexys 显示桥

顶层为 `src/rtl/nexys_hdmi/bridge_board_top_continuous.sv`。HDMI 接收模块检查光栅几何，跨时钟模块传递有效数据，帧所有权状态机保证未完成读写的缓冲区不被复用。帧 CRC、来源标记和完整扫描事件用于验证数据完整性及新帧计数。

DP 路径包括 AUX、EDID/DPCD、链路训练、主流处理、GTP 控制和健康监测。VGA 独立配置处理当前转换器 DPCD 电源读值为零的兼容情况：仍要求 D0 写入 ACK、等待和真实链路训练，不伪设电源确认位。最终实屏验收时前后读值均为 0x01；零值兼容分支的现有证据来自仿真。

## 4. 软件与交互

图片支持 ROI、x2/x4、切图和 PNG 导出；视频支持播放、逐帧、速度、循环、导入和 MP4 导出；摄像头支持实时处理、冻结、恢复和同帧快照。四种布局为 SR full、Compare、Nearest 和 Wipe。

图片质量基于原始 SR 与配对 HR 的同区域比较，PSNR-Y 裁去四像素边界，SSIM-Y 使用 11×11 高斯窗口。指标不包含显示缩放、工具栏和黑边，后台计算结果必须匹配当前图像、倍率、ROI 和代次。

摄像头界面 FPS 统计 PYNQ VDMA 确认的新帧，仅在 Fit Compare 显示。算法帧率、PYNQ 新显示帧率、Nexys 完整新扫描帧率、HDMI 30 Hz 与 DP 60 Hz 各有不同计数点。

## 5. 优化与实现结果

### 5.1 优化依据

| 问题或基线 | 改动 | 结果与证据范围 |
|---|---|---|
| x4 4-bit LUT 原始值容量 1,336,336 字节 | 使用 x4 5-bit LUT，104,976 字节 | 降低查表容量；最终正确性以对应 LUT 的黄金结果验证 |
| 校验、复制和缓存维护多次遍历完整画面 | ARM 像素校验/复制融合，显示缓冲和工具栏复用 | 历史 r5 两段 300 秒完整新帧验收达到 20 fps |
| r10 指标背景逐通道填充影响渲染与交互 | r11 整像素填充和缓存 | 历史短测 463 帧/20.47 秒，22.6143 fps，鼠标操作经人工确认 |
| 直接以扫描刷新次数估计吞吐 | 跟踪来源帧身份和完整扫描事件 | 将新结果与重复显示分开计数 |

没有完整同条件的 r10 持续帧率数据，因此不计算该项性能提升百分比。软件优化保持相应 FPGA 位流、LUT 和算法分辨率不变。

### 5.2 资源与时序

| 系统 | LUT | FF | BRAM | DSP |
|---|---:|---:|---|---:|
| PYNQ x2 完整系统 | 10,724 | 12,580 | 103 RAMB36 + 4 RAMB18 | 3 |
| PYNQ x4 完整系统 | 19,220 | 18,035 | 111 RAMB36 + 4 RAMB18 | 2 |
| Nexys VGA 完整显示桥 | 16,048 | 34,471 | 25 Block RAM Tile | 0 |

PYNQ 数据取自 `build/artifacts/pynq_x2`、`pynq_x4` 的 route utilization 报告，包含算法和显示系统；Nexys 数据取自独立 VGA 的 route utilization 报告。原报告保留工具版本、器件和层级，BRAM 表示方式按报告分别列出。

干净重建的 setup/hold 裕量为 PYNQ x2 0.194/0.028 ns、PYNQ x4 0.144/0.014 ns、默认 Nexys 0.106/0.039 ns；最终 VGA 为 0.106/0.039 ns。PYNQ 当前视频数据通路为 100 MHz，HDMI 为 1080p30，DP 为 1080p60；多时钟系统不以单一显示刷新率代表逻辑运行频率。

### 5.3 实测性能与验证

历史 r5，固定 480×270 输入、x4 输出、Fit：

| 布局 | 窗口 | Nexys 完整新扫描帧 | 帧率 |
|---|---:|---:|---:|
| SR full | 300 秒 | 6,527 | 21.7567 fps |
| Compare | 300 秒 | 6,727 | 22.4233 fps |

原始数据和复算程序位于 `report/performance/camera_r5_evidence.zip`。该结果绑定 r5 版本与测量条件，不作为当前 VGA 配置的长期可靠性结论。

已有参考模型 58 项、黄金检查 25 项、LUT 转换 5 项、PYNQ RTL 16 组验证记录。PS 主机回归中 243 项执行通过、5 项 ARM/Linux 专属跳过；主机控制器 190 项、启动器 32 项通过。Nexys 全帧仿真记录包含 5 次完整扫描、3 个新光栅帧和 2 次重复扫描。

VGA 最终候选实屏测试记录 1,424 个有效 HDMI 帧、0 个坏帧，界面、鼠标与板上按钮经人工确认，退出后恢复成功。后续普通演示另有 UART CRC/序号异常触发综合健康退出的记录；已归档用于说明验证边界，不据此推断 DP 物理故障原因。

## 6. 大模型协作与可复用 Skill

大模型协作用于方案分析、代码实现、测试生成和错误定位。现存真实记录包含用户需求、助手说明、实际错误及修复，索引位于 `report/collaboration/`。保留 NumPy 模拟缓冲区使用保留属性导致测试失败、改用独立属性后通过的过程。

Skill 将硬件调用拆为数据合同、独立参考、Overlay/接口验证、缓冲同步、DMA 收发、完成确认及释放。算法寄存器操作通过 hooks 提供，避免绑定 SR-LUT。离线示例为灰度阈值分割和多通道 int16 饱和增益。

已验证范围包括离线实例、模拟 CPU/设备内存分离、黄金比较、故意损坏检出、生命周期异常与独立目录运行。真实后端要求 PYNQ、匹配器件的 BIT/HWH 和 simple-mode 双向 AXI DMA；没有将同一个 BIT 跨器件使用，也尚无第二块 PYNQ 或两个新算子的实板验证。
