# Skill 提炼过程

## 从项目专用实现到可复用内容

原实现具有SR-LUT固定控制寄存器、倍率、RGBX布局及特定显示链路。这些是本队算法契约，直接复制驱动不能构成可换题目的模板。

本轮保留可泛化的流程：明确契约→独立黄金参考→核对产物与接口→分配/同步/传输/确认→按完成事件统计→保留失败记录。算法寄存器抽到hooks，图像和采样的shape/dtype抽到配置；输入输出类型禁止隐式转换。

## 形成判断的实际证据

| 观察 | 提炼内容 | 如何验证 |
|---|---|---|
| 原帧会话依赖固定SR-LUT寄存器和几何 | 控制hooks与数据合同 | 新核心不导入SR模块，两个不含超分的例子独立运行 |
| 超时不能保证硬件已停止 | Halted确认后才释放；失败quarantine | 模拟挂起/停止失败，检查没有free并禁止复用 |
| 缓存路径改变会影响数据可见性 | 显式同步、默认保守缓存策略 | mock分离CPU/设备存储，比较完整结果 |
| r11逐通道背景填充造成ARM渲染及鼠标回退 | 先分阶段测量，减少重复全帧写入 | 保留历史实施、ARM回归与短测记录 |
| r11非连续dtype view主机/ARM表现不同 | 显式步长与环境验证 | 保留原ARM纠错；新测试覆盖非连续输入 |
| 60Hz扫描可重复显示同一帧 | 固定窗口内按完成的新身份计数 | 原r5完整扫描证据与本轮重复事件测试 |
| 新包首次运行遇到NumPy2.x保留属性名 | 依赖API变化也需实际运行 | `initial_regression.json`与后续回归记录，不抹去原失败 |

## 已验证与未验证

- 新包验证为本机离线运行、fake PYNQ/MMIO、独立目录运行、原工程报告读取。
- 两个外部示例说明框架已脱离超分数据和算子；它们没有对应实板BIT/HWH。
- 原项目PYNQ-Z2的板端结果属于历史工程，不自动授予新模板相同资格。
- 尚无其他板卡实测，尚无跨模型提示词成功率统计。

适用边界依据接口定义和实际测试确定；未知格式、缺失接口或未验证的硬件缓存捷径不自动接受。
