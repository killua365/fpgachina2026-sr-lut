# 提示词工作流

适用：希望用大模型辅助 PYNQ 工程开发，同时保留可检查的接口和证据。题目外可用于滤波、信号处理、传感器与数值计算。以下为本轮**提炼版**提示词，不声称是历史对话逐字原文。

使用：复制一套模板，填入方括号字段和真实文件。模型输出后按对应检查执行；缺失数据必须标记未知。模型不是硬件验收主体，工具结果和实测记录才是判据。

## P1：算法到 PYNQ 接口与分工

```text
请依据下面材料设计 PYNQ 的 PS/PL 分工与接口，不自行补造寄存器或性能。
算法：[伪代码、独立参考实现、输入输出定义]
平台：[板卡/器件、PYNQ 与工具版本、时钟/内存]
约束：[正确性、延迟/吞吐目标、可用资源]
输出：
1. PS/PL 分工表，给出数据依赖、搬运量和取舍依据。
2. 每批输入输出的 shape、dtype、字节序、定点/饱和规则、字节长度。
3. AXI Stream 的 TLAST/TKEEP、simple DMA 限制、真实控制接口来源。
4. 尚缺信息及可执行的核验方法，禁止把估计数字写成实测。
5. 最小黄金测试、边界测试与上板接入步骤。
```

已应用：两个独立例子的合同与参考。传感器采用 `int16` 饱和，不做有符号溢出回绕。来源观察：本队固定尺寸、RGBX 布局和寄存器与算子强绑定，不能只换文件名就泛化。验证见例子结果和回归。

失效条件：没有算法数值定义、硬件接口文档或目标资源时，输出仅为待核验设计；该模板不生成可直接下载到任意板卡的 BIT。

## P2：黄金参考与边界验证

```text
请为以下 PYNQ 计算接口建立独立黄金参考与检查。
接口合同：[P1 输出]
实现：[被测代码/RTL接口]
要求：
1. 参考和被测实现不得共用同一个计算函数。
2. 明确整数精确比对、浮点 atol/rtol、非法形状、NaN/Inf处理。
3. 至少覆盖最小最大值、阈值等号、饱和、重复批次与输入步长。
4. 主动损坏一个输出，证明检查会失败。
5. 输出运行命令、实际检查结果与未验证项，不把模拟结果写成实板结果。
```

已应用：标量参考与独立向量模拟实现；故意损坏结果检出，覆盖 `int64` 比较差值溢出。来源观察：项目原像素参考不允许放宽误差来迁就布局/打包错误。验证见本包测试。

失效条件：算法本身存在非确定性或浮点语义未定时，须先约定误差；CRC 相等不等价于完整逐元素验证。

## P3：性能瓶颈与交互卡顿

```text
请分析性能下降，不先猜测 FPGA 或鼠标设置。
材料：[阶段耗时、原始事件、输入/输出尺寸、版本差异、运行环境]
测量点：[采集/提交/计算完成/显示完成，窗口与新帧身份]
输出：
1. 把事实、候选原因和未验证假设分开。
2. 区分 PS 预处理、DMA/PL、缓存同步、合成、显示及事件处理耗时。
3. 按证据给出一个最小修改，说明字节一致性和缓冲区所有权约束。
4. 给出前后相同条件的验证；不能以减少清晰度或少做校验换取目标。
5. 瞬时/短测/持续结果分别报告，不把刷新率当有效帧率。
```

来源与已验证效果：历史 r11 把逐通道背景填充改为正确布局的 RGBX 整字填充，短测及鼠标体验恢复；ARM NumPy 1.21 非连续视图曾失败并修正。历史 r5 的持续结果单独记录。新模板本轮基于这些实际证据完成复盘，不声称在其他模型、平台上多次稳定成功。

外部场景：PYNQ 视觉仪器、波形显示、监控界面。失效条件：没有阶段数据、前后输入不同、不同计时器未对齐时不能归因；RGBX 优化不可套到任意 RGB 三通道缓冲区。

## P4：部署与异常诊断

```text
请检查一次 PYNQ 部署/传输故障。
材料：[BIT/HWH清单和哈希、IP信息、时序/资源报告、异常日志、启动步骤]
输出：
1. 先做离线文件和接口检查，列出每项实际证据。
2. 按症状定位文件不匹配、IP缺失、长度/TLAST、缓存同步或DMA状态。
3. 超时不等于硬件停止；释放前需证明DMA停止，不能自动释放仍被占用的缓冲区。
4. 换Overlay前停止采集、提交和后台旧句柄访问。
5. 报告通过/失败/未检查/不支持，不把缺项当通过。
```

来源观察：本队保留文件身份、时序检查、DMA 停止与有序恢复。已应用：原始 Vivado 报告校验、配置损坏检出、模拟超时且停止失败时保留缓冲区。外部场景为一般 PYNQ Overlay 交付及实验室复现。

失效条件：AXI 总线挂死、断电、JTAG 或网络物理故障不能仅靠 Python 恢复；主机超时不证明板端程序已停止。

## 验证范围

本轮由当前编码助手按以上步骤组织实现与复核；实际输入、决策、失败、纠正和结果见 [协作记录](../evidence/collaboration_record.md)。提示词没有跨模型成功率统计，迁移到新模型时需运行同样的检查，不能仅凭回答流畅就判定有效。
