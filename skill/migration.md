# 本队题目之外的适用场景

本队功能是图片、视频、摄像头的 SR-LUT 超分。以下复用只要求通用的数据流与控制接口，不要求采用超分算法。

| 外部场景 | 可直接复用的 Skill | 需要替换的内容 | 验证状态与不适用条件 |
|---|---|---|---|
| 工业灰度阈值分割、运动区域掩膜 | 接口契约、DMA 批次模板、黄金比对、故意损坏检出 | 图像尺寸、阈值寄存器、IP 名称、BIT/HWH | `image_threshold` 离线已验证；没有该算子的板端比特流 |
| 摄像头 Sobel、卷积滤波、去噪 | 缓冲区复用、参考比对、Overlay 载入校验、真实新帧统计 | 边界填充、通道顺序、系数、输出几何、TLAST | 迁移方案；卷积行缓冲/多输入协议需专门适配 |
| 多通道 ADC 采样校准、传感器增益与限幅 | `int16` 合同、饱和参考、DMA 批次生命周期、吞吐统计 | 采样布局、增益系数、批次长度、时间基准 | `sensor_gain` 离线已验证；连续流需定义批次边界 |
| 音频 FIR、FFT 频谱处理 | PS/PL 划分提示词、数值容差校验、DMA 超时诊断 | 定点缩放、复数布局、FFT 排序、参数和参考结果 | 迁移方案；当前比较器不直接接收 complex，须显式拆为实/虚数组 |
| 小矩阵运算或推理前处理 | 输入输出契约、版本与哈希记录、资源时序检查 | 矩阵布局、批次、量化规则、控制接口 | 迁移方案；直接读写 DDR 的 m_axi 加速核不等于 AXI Stream DMA，需另写后端 |
| PYNQ 图形界面或实时仪器显示 | ARM 绘制瓶颈定位、缓存/步长检查、帧身份统计、快照所有权 | 像素格式、设备完成事件、界面几何 | 原项目已验证方法；RGBX uint32 填充仅适用于正确对齐及字节布局 |
| 其他 FPGA 工程的交付与持续集成 | SHA-256、黄金比较、时序资源报告解析、提示词复核流程 | 器件、报告格式、文件清单、资源限制 | 工具离线可用；PYNQ 调用部分不能直接用于非 PYNQ 平台 |

## 换题目

1. 写出每批输入/输出的形状、dtype、字节序、定点规则、允许误差和帧结束条件。
2. 先实现独立软件参考。整数比较默认逐元素完全相同；不要用宽松容差掩盖类型错误。
3. 保留 `BatchSession`，替换配置及控制 hooks。控制 hooks 的 `configure/start/done` 必须来自新 IP 的真实寄存器契约。
4. 先用 mock 检查控制与内存所有权，再用新算子 BIT/HWH 进行板端比对。
5. 在相同输入、同一完成事件与固定时窗下记录新性能；不能继承本队 fps。

## 换板卡

1. 确认新板具有适配的 PYNQ 镜像，记录 PYNQ/Python/NumPy/内核版本。
2. 用新板器件、引脚、PS 配置、DDR、时钟与地址映射重新构建 Overlay。不得把 PYNQ-Z2 的 BIT 下载到另一器件。
3. 更新 profile 中同次生成的 BIT/HWH、SHA-256、IP 全层级名称。检查 `ip_dict`；HWH 有寄存器描述时可查看 `register_map`，否则按真实文档使用 `read/write`。
4. 确认 simple mode 双向 AXI DMA、长度上限、总线宽度、DRE/地址对齐和正确 TLAST。
5. 使用目标板默认 PynqBuffer 同步语义，不默认启用本队 ACP 优化；先跑小批、边界批和重复批。
6. 正确性、故障收尾、时序及持续性能分别记录。修改后只有取得新板证据，才能标记为“跨板卡已验证”。

## 直接可用与需要适配的区别

校验工具和文档可独立取走；板端模板复用的是程序结构，不承诺任何 Overlay 无配置即插即用。新板和新算子的控制寄存器、缓存路径、流量上限属于其自己的硬件契约。
